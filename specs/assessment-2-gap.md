## Blockers

Deployed `search_catalogue` embeds through `OLLAMA_HOST`. On 26 October 2026 that secret was an account-less Cloudflare quick tunnel to a local proxy. The proxy accepts only `POST /api/embed` for `nomic-embed-text` and forwards it to Ollama on `127.0.0.1:11434`. The URL is not stored in this repository. Cloudflare does not guarantee the tunnel. When Ollama, the proxy, or the tunnel is down, catalogue search cannot embed a query. The retrieval report did not use that tunnel. `supabase/migrations/20261027004700_match_knowledge_exact_search.sql` was applied manually. It sorts the stored vectors exactly and does not change chunk rows or embeddings. Catalogue search was not repeated after that apply. The deployed chat call still times out at 20 seconds. The 45-second timeout is only in the local function.

The level classifier is still stopped on the Gemini plan quota, with 7 held-out rows uncalled. The submission tag, role checks on the live URL, role credentials, a full test log, and the Dev Control Tower submission are still open.

## Automations

Both workflows are implemented.

- Course completion is event-driven. Mark complete on `/student/my-courses/$courseId` inserts one `lesson_completions` row. `sync_enrollment_progress` sets progress. The existing `enrollments_sync_status` trigger sets `completed` at 100. `enrollments_issue_certificate` then inserts one certificate, one `course_completed` notification, and one `student_completed_course` notification. A second transition inserts nothing.
- Assignment reminders run as `POST /api/assignment-reminders`. The route accepts only the cron bearer, then inserts `assignment_due` rows with the service-role client. The stages are 72h, 24h, and 1h, in non-overlapping windows. A null due date, a due date outside the next 72 hours, a student who already submitted, and a stored stage key produce no new row. A missed hour sends only the stage that is still open. The hourly schedule is confirmed. An earlier local POST to the dev server with no bearer returned 500 `Server configuration error` and did not run the job. That missing-secret check is not the scheduled run.

`supabase/migrations/20261016220000_lesson_completions.sql` and `supabase/migrations/20261016221000_certificates_and_notifications.sql` are present on the linked database. The tables, indexes, policies, grants, and functions were already there, and no rows were dropped. The certificate trigger had to be recreated as `after update` with the same completed-status condition. `update of status` does not run when `sync_enrollment_progress` writes `progress` and `enrollments_sync_status` assigns `status` in that update. The reminder endpoint is implemented, and its hourly schedule is confirmed. Both automations work.

The latest focused run passed 24 tests across `src/features/notifications/workflows.test.ts`, the learning, My Courses, and instructor dashboard screens, and the two migration audits. Those tests use mocks and the SQL files. They do not open a browser and they do not apply SQL.

## RAG ingestion

Retrieval code, `match_knowledge`, and `scripts/seed-rag-chunks.ts` are implemented. `supabase/migrations/20261016222000_rag_chunks.sql` is applied on the linked project. The seed writes course and lesson chunks before FAQ rows. It skips unchanged `source_key` values unless `RAG_EMBED_REPLACE_ALL` is set, and it stops new FAQ rows once the stored total reaches `RAG_EMBED_RECORD_LIMIT` (default 300). Embeddings come from Ollama `nomic-embed-text`. A failed embed stops the run and keeps rows already written.

On 19 October 2026 a one-text `gemini-embedding-001` probe returned 768 dimensions. The seed was then resumed with `RAG_EMBED_RECORD_LIMIT` 10000 so missing catalogue chunks stayed first and FAQ rows could continue toward 5,000. It kept 300 unchanged rows, embedded 96 more, and stopped on HTTP 429 for the plan quota. A later resume with a new key kept those 396 rows, embedded 176 more FAQ rows, and stopped again on the same plan-quota 429. A count of `rag_chunks` was then 572: 6 course, 13 lesson, and 553 FAQ. On 21 October 2026 the seed was resumed with `RAG_EMBED_RECORD_LIMIT` 10000. It kept those 572 rows, embedded 104 more (2 course, 12 lesson, and 90 FAQ), and stopped on HTTP 429 for the plan quota. A count of `rag_chunks` is 676: 8 course, 25 lesson, and 643 FAQ. The 5,000 FAQ bar is not met. The level classifier was not called after that stop. On 21 October 2026 `scripts/rag-evaluation.ts` scored the stored 676 Gemini chunks. Those figures are not comparable to the later Nomic corpus.

On 26 October 2026 the seed switched to Ollama `nomic-embed-text` at 768 dimensions and upserted cached vectors by `source_key`. It did not delete rows. A count of `rag_chunks` is 5,040: 9 course, 31 lesson, and 5,000 FAQ. Every row has an embedding. `scripts/rag-evaluation.ts` then scored that corpus on the same machine. Matching Hit@5 is 1.000 and MRR@5 is 0.950. Noisy Hit@5 is 0.867 and MRR@5 is 0.291, so the noise delta is 0.133. Extreme keyed Hit@5 is 0.133 and MRR@5 is 0.080. Extreme rejection at cosine 0.75 is 1.000 for all 15 out-of-corpus queries. Hit@5 and MRR@5 are blank on that row. The mean top-1 cosine for that set is 0.493. The 0.75 cutoff stays. The 5,000 FAQ bar is met. Deployed query embeddings use the temporary Cloudflare tunnel in the blockers section. That tunnel was not used for this score.

## Level accuracy

`scripts/level-accuracy.ts` keeps the seed-42 80/20 split (160 train, 40 test). Accuracy is correct predictions divided by successfully classified held-out rows. Infrastructure failures are excluded. The report is written only when accuracy is at least 0.70 and every held-out row was classified.

An earlier live run printed 0.400 because quota failures were counted as wrong answers. That figure is not the accuracy under the current rule.

On 19 October 2026 the script resumed 16 saved predictions in `scripts/fixtures/level-progress.json`, then Gemini returned HTTP 429 for the plan quota and the run stopped. Those saved predictions were left in place. On 21 October 2026 the script resumed those 16 predictions, classified 16 more, and stopped again on HTTP 429 for the plan quota. The earlier 16 predictions were unchanged. Train count 160. Test count 40. Classified 32. Coverage 0.800. Accuracy on the classified rows 1.000. Classification errors 0. Infrastructure errors 1. Not attempted 7. The confusion matrix is 13 beginner, 10 intermediate, and 9 advanced, all correct. `docs/assessment-2/level-accuracy.md` records that partial result. The 0.70 target is not met.

`src/test/level-accuracy.test.ts` and `src/features/ai/gemini-log.test.ts` passed together (13 tests) after the scoring change. Those tests mock Gemini.
